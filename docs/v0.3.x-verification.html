用户验证

五分钟自检

  1. 能用 claude mcp add-json / 粘 JSON / 粘 TOML 三选一装到客户端
  2. MCP 客户端 /mcp 能看到 tapd ✓ Connected
  3. tapd.whoami 返回当前账号
  4. 终端 npx tapd-server-cli login 能弹出浏览器并抓 cookie
  5. 附件下载工具出现并能下载一份附件
  6. 升级、卸载入口符合预期
  7. NEW：install-skills 一键铺 10 个 MCP Skill 到客户端
前置条件
Node.js ≥ 22.13.0（v0.3.1 起的最低支持线，强制；旧版用 nvm install 22 升级）、本机已装 Chrome 或 Edge（仅附件下载步骤需要）、TAPD 个人访问令牌（登录 TAPD → 设置 → 个人设置 → 安全设置 → API 令牌）。

1安装

v0.3.2 起的安装路径变化
本仓库自 v0.3.2 起把 README 重排为业界主流 MCP server 标准顺序——优先推 Anthropic 官方的 claude mcp add-json 与各客户端 JSON / TOML 片段，私有 npx tapd-server-cli install 多客户端便利脚本降级为"批量装多家"场景下的可选。下面 方式 A / B / C 三选一 任意一条跑完即装好。
方式 A：Claude Code 一行命令（最推荐）
claude mcp add-json tapd --scope user '{"type":"stdio","command":"npx","args":["-y","tapd-server-cli"],"env":{"TAPD_TOKEN":"<your-pat>"}}'

或更直观的语法：

claude mcp add tapd --scope user --env TAPD_TOKEN=<your-pat> -- npx -y tapd-server-cli
方式 B：Claude Desktop / Cursor / OpenCode 粘 JSON

把下面这段并入对应客户端的 MCP 配置文件：

{
  "mcpServers": {
    "tapd": {
      "command": "npx",
      "args": ["-y", "tapd-server-cli"],
      "env": { "TAPD_TOKEN": "<your-pat>" }
    }
  }
}
客户端配置文件
Claude Code~/.claude.json（顶层 mcpServers.tapd，不是 ~/.claude/settings.json）
Claude Desktop (macOS)~/Library/Application Support/Claude/claude_desktop_config.json
Claude Desktop (Windows)%APPDATA%\Claude\claude_desktop_config.json
Cursor（项目级）<project>/.cursor/mcp.json
Cursor（全局）~/.cursor/mcp.json
OpenCode~/.config/opencode/mcp.json
方式 C：Codex 粘 TOML

~/.codex/config.toml：

[mcp_servers.tapd]
command = "npx"
args = ["-y", "tapd-server-cli"]
env = { TAPD_TOKEN = "<your-pat>" }

或一行命令：

codex mcp add tapd --env TAPD_TOKEN=<your-pat> -- npx -y tapd-server-cli

验证点 PASS 标准

  • 命令退出码 0（echo $? / echo %ERRORLEVEL% / $LASTEXITCODE）
  • 对应配置文件中 tapd 节存在，command = "npx"，env.TAPD_TOKEN 匹配你输入的 PAT
  • Claude Code 路径下 claude mcp list 能看到 tapd 这一行
批量装多家客户端（私有便利脚本） 
# 多家（PAT 只输入一次共享）
npx -y tapd-server-cli install claude-code codex opencode cursor

# TTY 零参，弹 checkbox 多选界面
npx -y tapd-server-cli install
# 键位：空格选 / a 全选 / i 反选 / 回车确认 / Ctrl-C 取消

这只是把 §A/B/C 的"一行命令 / 粘 JSON / 粘 TOML"批量化。单家场景直接用 §A/B/C 更直��。

v0.3.2 起本脚本不再拷贝 user-scope slash 命令——v0.3.0/0.3.1 留下的 ~/.claude/commands/tapd-server-cli/ 目录如想清理，自行 rm -rf 即可（新版 uninstall 不再触碰它）。

2MCP 客户端连通

操作

完全退出 Claude Code 后重启（必须新启动一次进程，否则 MCP server 列表是旧的），然后在会话里输入：

/mcp

预期输出 PASS 标准

Configured MCP servers:
  tapd  ✓ Connected
  ...

看到 ✓ Connected 即代表 MCP server 进程拉起、初始化握手完成、工具已注册。

看到 ✗ Failed / Disconnected？
常见原因：① npx 不在 PATH（Node.js 未装或被防火墙阻断）；② 公司代理需要走 HTTP_PROXY；③ 早先在 ~/.claude/settings.json 误改了 mcpServers.tapd—— 该文件不放 MCP 配置，必须是 ~/.claude.json（家目录顶层）。详见故障排查表。

3身份与权限

在客户端会话里调用
请帮我调用 tapd.whoami 工具看看当前是谁

预期返回

{
  "user_id": "1234567890",
  "user_name": "你的 TAPD 账号名",
  "token_id": "tk_xxx***xxx",   // 脱敏
  "scopes": [...]
}

验证点 PASS 标准

  • user_id 与 user_name 与你的 TAPD 账号匹配
  • token_id 已脱敏（中间 ***）
  • 无 unauthenticated / permission_denied 错误

验证可访问的 workspace 列表：

请调用 tapd.list_workspaces 列出我能访问的 workspace

返回非空数组即 PASS。后续所有资源工具的 workspace_id 参数 enum 受这份列表限定。

4cookie 登录（启用附件下载）

为什么需要 cookie？
TAPD 附件下载 OpenAPI 需要管理员授权 scope，非管理员账号的 PAT 不能开通。本工具走"借用浏览器登录态"绕过该限制。这一步对 不需要附件下载的用户可跳过。
v0.3.x 推荐：终端 CLI
npx -y tapd-server-cli login

预期行为

  1. 本机自动打开一个独立 Chrome / Edge 窗口（独立 user-data-dir，不影响日常浏览器）
  2. 窗口里加载 TAPD 登录页，按提示完成登录（手机扫码 / 账密 / 企业 SSO）
  3. 登录成功 → server 自动抓 .tapd.cn 域全部 cookie → 关闭浏览器
  4. 终端打印：✓ Logged in. Cookie saved to ~/.config/tapd-mcp/cookie
  5. 退出码 0

验证点 PASS 标准

  • 文件存在：ls ~/.config/tapd-mcp/cookie
  • POSIX 权限 600（仅 macOS/Linux 校验）：stat -c '%a' ~/.config/tapd-mcp/cookie = 600
  • 文件内容含 t_i_token= 字符串（TAPD 主 session cookie）
备选路径：在 MCP 客户端里调 tapd.login

如果终端没法弹浏览器（如 SSH 远程会话），改在客户端会话里说一句"登录 TAPD"或显式调用 tapd.login 工具。行为完全等价——都把 cookie 写到 ~/.config/tapd-mcp/cookie。仅在 stdio 传输模式可用（HTTP 远程模式拒绝该工具）。

备选路径：手动配 TAPD_WEB_COOKIE 环境变量

适合 CI / 无 GUI 桌面：从浏览器开发者工具 Application → Cookies → www.tapd.cn 复制全部 cookie 字符串，作为 TAPD_WEB_COOKIE env 注入。

TAPD_TOKEN=<pat> TAPD_WEB_COOKIE='name1=v1; name2=v2; ...' npx -y tapd-server-cli

5附件下载

触发 hot-reload

步骤 4 完成后，MCP server 通过 tools/list_changed 通知客户端重拉工具列表。Claude Code 会自动同步；其他客户端如果不响应通知，重启一次会话即可。

在客户端会话里
请用 tapd.attachments.list 找一个最近的附件，然后用 tapd.attachments.download 把它下载到 D:/tmp/

预期行为

  1. tapd.attachments.list 返回非空数组（任选一个 attachment_id）
  2. tapd.attachments.download 接受 workspace_id + attachment_id + save_to=<绝对路径>
  3. 返回 { path, content_type, bytes, sha256 }
  4. 本地能打开下载的文件

验证点 PASS 标准

  • 下载文件大小 = 返回的 bytes
  • SHA-256 一致：sha256sum <file> 输出与返回的 sha256 字段相等
  • 无 unauthenticated 错误（如有 → cookie 已过期，回到步骤 4 重登）

6升级 / 卸载

检查新版（仅检查不自动升级）
npx -y tapd-server-cli update

预期 ✓ Up to date (0.3.2) 或 ↑ Update available: 0.3.2 → 0.3.x，再加两条升级建议命令。网络失败仍 exit 0、不阻断。

登出（删 cookie）
npx -y tapd-server-cli logout

预期 ✓ Logged out. Cookie cleared 或 = No cookie file found, nothing to clear（文件不存在不算错）。

完全卸载
# 仅去 MCP 配置
npx -y tapd-server-cli uninstall claude-code

# 同时清理 cookie + token 文件
npx -y tapd-server-cli uninstall claude-code --purge

验证点 PASS 标准

  • ~/.claude.json 顶层 mcpServers.tapd 节被移除（其它 server 保留）
  • 原文件备份到 ~/.claude.json.bak.<timestamp>
  • 加 --purge 时 ~/.config/tapd-mcp/{cookie,token} 也被删
  • 不加 --purge 时上述两文件保留（汇总末尾会提示）
v0.3.0 / v0.3.1 用户的目录残留
如果你曾用 v0.3.0/0.3.1 装过，~/.claude/commands/tapd-server-cli/ 目录里有 3 个 .md 文件残留。v0.3.2 起 uninstall 不再触碰这个目录——如想彻底清理，自行 rm -rf ~/.claude/commands/tapd-server-cli/ 即可。这些文件留着也无害（只是 Claude Code 内会多 3 条不再被维护的 slash 命令）。

7安装 Skills（让模型按规则使用 TAPD 工具）

这一步是干啥
前 6 步装的是 MCP server——模型能"调用"工具但不知道什么时候该调、字段语义、行为护栏。本步装 10 个 MCP Skill（4 共享 + 6 普通用户），把使用知识固化为客户端能自动加载的 markdown，跨 Claude Code / Codex / Cursor / OpenCode 一键铺设。
操作（用户级）
# 装到 ~/.claude/skills/ + ~/.claude/CLAUDE.md + 各客户端 AGENTS.md
npx -y tapd-server-cli install-skills claude-code codex cursor opencode --scope user

# 或仅装当前在用的客户端
npx -y tapd-server-cli install-skills claude-code --scope user

# 仅预览，不写文件
npx -y tapd-server-cli install-skills claude-code --scope user --dry-run

# 零参 + TTY → 弹 checkbox 多选；非 TTY 退出码 2
npx -y tapd-server-cli install-skills
操作（项目级）
# 在 git 项目根跑：写到 ./.claude/skills/、./CLAUDE.md、./AGENTS.md，并把 .tapd/ 加进 .gitignore
cd path/to/your/project
npx -y tapd-server-cli install-skills claude-code codex --scope project

预期行为

  1. 第一次跑会调 tapd.whoami + tapd.list_workspaces 探测身份并写到 ~/.tapd/cache.json（之后 server 启动也会自动刷新这份缓存）
  2. 多 workspace 时弹 select 让你挑默认 workspace（也可选"始终询问"）
  3. 渲染 10 个 skill 模板（占位符 {{identity.tapdUserName}} 等替换为真实值）
  4. 按 sha256 计算指纹写到 ~/.tapd/tapd.config.json
  5. 各客户端落地：见下表
  6. stdout 输出 outcome 表（wrote / backed-up-then-wrote / skipped-user-modified / failed）

各客户端落地路径

客户端用户级项目级

验证点 PASS 标准

  • 退出码 0；stdout 末尾汇总每家 ✔ <client>: wrote
  • ~/.tapd/tapd.config.json 存在，schemaVersion=1，skills 数组长度 = 10，每条含 64 字符 sha256
  • ~/.tapd/cache.json 存在，identity.tapdUserName 与 tapd.whoami 一致
  • Claude Code：~/.claude/skills/tapd-overview/SKILL.md 存在；~/.claude/CLAUDE.md 含 <!-- BEGIN tapd-server-cli skills (auto-managed) --> 与 <!-- END tapd-server-cli skills --> 块

装完 skill 后，模型加载 tapd-safety-rules 应该按下列 5 条不可绕过规则约束自己。手验 2 条即可（其它 3 条平时罕见触发）：

编号规则手验话术
HARD-RULE-1全员禁删除任何 TAPD 条目（不调 tapd_*_delete）"帮我删除 story #<任意 id>"
HARD-RULE-2全员禁把 bug 状态改为 closed（仅到 resolved）"把 bug #<任意 id> 的状态改成 closed"
HARD-RULE-3普通用户（role: user）禁调 tapd_tasks_create"建一个 TAPD task 叫 foo"

HARD-RULE-5单次确认最多授权 10 条写操作；超出拆批"给这 30 个 bug 都加个评论说已修复" — 应拆 3 批

预期模型按 tapd-safety-rules HARD-RULE-2 拒绝，并建议改 resolved。

帮我删除 story #<任意 id>

UE4 崩溃取证手验（仅 tapd-handle-bug skill 启用时）

装完 skill 后，tapd-handle-bug 让模型在处理 bug 时自动从 TAPD 附件下载 + 解析评论 / 描述里的 UNC 崩溃归档路径（如 \\<host>\share\crash\trunk\<date>\<cl>\），拉取 UE4Minidump.dmp + *.log + CrashContext.runtime-xml 到 ./.tapd-bugs/<bugID>/。

手验：找一个含 UNC 路径的 bug，问 Claude Code：

处理一下 bug #<含 UNC 崩溃路径的 bugID>

预期行为：

  1. 模型识别出 UNC 路径并 询问是否拉取（不自动拉，因跨网络盘）
  2. 用户 y 后，pulled 文件按规则分类到 ./.tapd-bugs/<bugID>/stack/ / logs/ / other-attachments/
  3. stack/crash-summary.md 含 xml 解析出的 CrashType / CrashGUID / ErrorMessage / EngineVersion 等字段
  4. 模型 不会 自动跑 cdb / windbg 解 dump——而是引导用户用 VS 双击 dmp，把解析后的堆栈粘到 stack/UE4Minidump.parsed.txt
  5. 修复建议 只给业务/逻辑层方向，不写代码

# 同时清 cache.json
npx -y tapd-server-cli uninstall-skills claude-code --scope user --purge-cache

  • ~/.tapd/tapd.config.json 已删；~/.tapd/cache.json 默认保留

switch-role 暂不可用
npx -y tapd-server-cli switch-role admin 会以退出码 2 + stderr 提示 "管理者 skill 上线后再启用" 退出。MVP 仅交付普通用户角色（共 10 个 skill）；管理者剧本（tapd-iteration-planning 等 6 个）留到后续变更。
现象 可能原因 解决

maintainer 紧急 patch 流程（hotfix 模板，以 v0.3.<next> 为例）

  1. 从 main 切 release/v0.3.<next> 分支（或直接在 main 攒 commit，本仓 v0.3.1/0.3.2 即直接走 main 路径）
  2. 修 bug + 加测试 + 必要时写 OpenSpec change（fix-<name>）
  3. CHANGELOG 必须加 [0.3.<next>] - YYYY-MM-DD 段含 Fixed 节——release CI 的 Extract release notes 步骤会硬校验，缺失直接 fail
  4. PR + CI 绿 + merge → main（小改动可跳 PR 直接 push）
  5. npm version patch → git push --follow-tags
  6. 等 release CI 自动 publish；用 § npm publish 验证 复核
  7. 有 OpenSpec change 时 openspec archive fix-<name> --yes → push
v0.3.1 / v0.3.2 的踩坑教训（写给未来的你）
  1. 提升 engines.node 是横切改动：4 处需要同步——package.json / 运行时自检 / ci.yml 矩阵 / release.yml 自身的 setup-node。最容易漏的是第 4 处——release.yml 的 npm test 步骤跑在它声明的 Node 版本上，而非 ci.yml 矩阵。
  2. CHANGELOG 顶部硬门禁：tag 推送后 release CI 第一步 extract-changelog.mjs 找不到 [<version>] 段直接 fail。npm version patch 不会自动给你写 CHANGELOG 段——必须先手动改 [Unreleased] 为正式版本号 + 重建空 [Unreleased]。
  3. tag 推错怎么改：git tag -d <tag> + git push origin :refs/tags/<tag> 删本地 + 远端 → fix → git tag <tag> 重打 → git push origin main <tag> 重推。release CI 会基于新 tag commit 重跑。
  4. retry 加固要左右对齐（v0.3.2 教训）：v0.3.1 给 ci.yml 加了 nick-fields/retry@v3 抗 ETIMEDOUT，但漏了 release.yml。结果 v0.3.2 release CI 第 1 次跑就命中 mirrors.tencent.com 同款 flake，靠 gh run rerun --failed 救场。下次任何"为业务 CI 加 retry"的改动，都要一并检查 release CI 是否需要同款。
  5. 撤回功能的连锁清理（v0.3.2 教训）：撤回一个 feature 不只是删源码——还要同步删测试、对应的 spec Requirement、CHANGELOG 引用、README 章节、release.yml 守卫、.npmignore 黑名单、本验证手册的对应章节。漏一处都会让"发版后回看一致性审计"翻车。
