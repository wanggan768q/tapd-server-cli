tapd-server-cli v0.3.x 验证手册 本手册对齐 v0.3.x 主线（plugin 路径已撤回，user-scope commands + CLI 子命令双路径）

最近发布：v0.3.1（2026-05-30，含 Node 22.13+ 自检）｜ 初始发布：v0.3.0（2026-05-29）｜ npm tarball：tapd-server-cli@latest ｜ GitHub Releases：列表

v0.3.0 主要变化：① 删除 Claude Code plugin 体系（marketplace add 路径撤回）；② install claude-code 同时拷贝 user-scope slash 命令到 ~/.claude/commands/tapd-server-cli/；③ 新增 CLI 子命令 login / logout / update，替代被移除的 tapd.update MCP 工具。

v0.3.1 增量：① main() 入口新增 Node.js 版本运行时自检（< 22.13.0 直接 exit 2 + 中文友好提示）；② engines.node 同步提升到 >=22.13.0；③ CI 矩阵升级到 Node 22/24，npm ci 加 3 次 retry 抗 transient flake。

用户验证

五分钟自检

  1. npm 包能下载、能写入客户端配置
  2. MCP 客户端 /mcp 能看到 tapd ✓ Connected
  3. tapd.whoami 返回当前账号
  4. 终端 npx tapd-server-cli login 能弹出浏览器并抓 cookie
  5. 附件下载工具出现并能下载一份附件
  6. 升级、卸载入口符合预期
前置条件
Node.js ≥ 22.13.0（v0.3.1 起的最低支持线，强制；旧版用 nvm install 22 升级）、本机已装 Chrome 或 Edge（仅附件下载步骤需要）、TAPD 个人访问令牌（登录 TAPD → 设置 → 个人设置 → 安全设置 → API 令牌）。

1安装

命令
npx -y tapd-server-cli install claude-code

命令会做三件事：

  1. 提示输入 TAPD 个人访问令牌（PAT）—— 隐藏输入，不会留 shell history
  2. 优先调 claude mcp add-json --scope user（不可用时回退手写 ~/.claude.json 顶层 mcpServers.tapd）
  3. 把 commands/*.md 拷到 ~/.claude/commands/tapd-server-cli/，启用 /tapd-server-cli:login 等 user-scope slash 命令

预期输出（成功）

请输入 TAPD 个人访问令牌:  ********
已通过官方 CLI 注册 Claude Code：<via claude mcp add-json --scope user>
✓ user-scope commands installed: login.md, logout.md, update.md
─── 安装结果：───
✔ claude-code  <via claude mcp add-json --scope user>

验证点 PASS 标准

  • 退出码 0（echo $? 在 Linux/macOS；echo %ERRORLEVEL% 在 Windows cmd；$LASTEXITCODE 在 PowerShell）
  • 检查文件已生成：ls ~/.claude/commands/tapd-server-cli/ 含 login.md / logout.md / update.md
  • 检查配置：grep -A 5 '"tapd"' ~/.claude.json 含 "command": "npx" 与 "args": ["-y", "tapd-server-cli"]
同时装多家客户端 / 交互式选择 
# 多家（PAT 只输入一次共享）
npx -y tapd-server-cli install claude-code codex opencode cursor

# TTY 零参，弹 checkbox 多选界面
npx -y tapd-server-cli install
# 键位：空格选 / a 全选 / i 反选 / 回车确认 / Ctrl-C 取消

2MCP 客户端连通

操作

完全退出 Claude Code 后重启（必须新启动一次进程，否则 MCP server 列表是旧的），然后在会话里输入：

/mcp

预期输出 PASS 标准

Configured MCP servers:
  tapd  ✓ Connected
  ...

看到 ✓ Connected 即代表 MCP server 进程拉起、初始化握手完成、工具已注册。

看到 ✗ Failed / Disconnected？
常见原因：① npx 不在 PATH（Node.js 未装或被防火墙阻断）；② 公司代理需要走 HTTP_PROXY；③ 早先在 ~/.claude/settings.json 误改了 mcpServers.tapd—— 该文件不放 MCP 配置，必须是 ~/.claude.json（家目录顶层）。详见故障排查表。

3身份与权限

在客户端会话里调用
请帮我调用 tapd.whoami 工具看看当前是谁

预期返回

{
  "user_id": "1234567890",
  "user_name": "你的 TAPD 账号名",
  "token_id": "tk_xxx***xxx",   // 脱敏
  "scopes": [...]
}

验证点 PASS 标准

  • user_id 与 user_name 与你的 TAPD 账号匹配
  • token_id 已脱敏（中间 ***）
  • 无 unauthenticated / permission_denied 错误

验证可访问的 workspace 列表：

请调用 tapd.list_workspaces 列出我能访问的 workspace

返回非空数组即 PASS。后续所有资源工具的 workspace_id 参数 enum 受这份列表限定。

4cookie 登录（启用附件下载）

为什么需要 cookie？
TAPD 附件下载 OpenAPI 需要管理员授权 scope，非管理员账号的 PAT 不能开通。本工具走"借用浏览器登录态"绕过该限制。这一步对 不需要附件下载的用户可跳过。
v0.3.x 推荐：终端 CLI
npx -y tapd-server-cli login

预期行为

  1. 本机自动打开一个独立 Chrome / Edge 窗口（独立 user-data-dir，不影响日常浏览器）
  2. 窗口里加载 TAPD 登录页，按提示完成登录（手机扫码 / 账密 / 企业 SSO）
  3. 登录成功 → server 自动抓 .tapd.cn 域全部 cookie → 关闭浏览器
  4. 终端打印：✓ Logged in. Cookie saved to ~/.config/tapd-mcp/cookie
  5. 退出码 0

验证点 PASS 标准

  • 文件存在：ls ~/.config/tapd-mcp/cookie
  • POSIX 权限 600（仅 macOS/Linux 校验）：stat -c '%a' ~/.config/tapd-mcp/cookie = 600
  • 文件内容含 t_i_token= 字符串（TAPD 主 session cookie）
备选路径：在 MCP 客户端里调 tapd.login

如果终端没法弹浏览器（如 SSH 远程会话），改在客户端会话里说一句"登录 TAPD"或显式调用 tapd.login 工具。行为完全等价——都把 cookie 写到 ~/.config/tapd-mcp/cookie。仅在 stdio 传输模式可用（HTTP 远程模式拒绝该工具）。

备选路径：手动配 TAPD_WEB_COOKIE 环境变量

适合 CI / 无 GUI 桌面：从浏览器开发者工具 Application → Cookies → www.tapd.cn 复制全部 cookie 字符串，作为 TAPD_WEB_COOKIE env 注入。

TAPD_TOKEN=<pat> TAPD_WEB_COOKIE='name1=v1; name2=v2; ...' npx -y tapd-server-cli

5附件下载

触发 hot-reload

步骤 4 完成后，MCP server 通过 tools/list_changed 通知客户端重拉工具列表。Claude Code 会自动同步；其他客户端如果不响应通知，重启一次会话即可。

在客户端会话里
请用 tapd.attachments.list 找一个最近的附件，然后用 tapd.attachments.download 把它下载到 D:/tmp/

预期行为

  1. tapd.attachments.list 返回非空数组（任选一个 attachment_id）
  2. tapd.attachments.download 接受 workspace_id + attachment_id + save_to=<绝对路径>
  3. 返回 { path, content_type, bytes, sha256 }
  4. 本地能打开下载的文件

验证点 PASS 标准

  • 下载文件大小 = 返回的 bytes
  • SHA-256 一致：sha256sum <file> 输出与返回的 sha256 字段相等
  • 无 unauthenticated 错误（如有 → cookie 已过期，回到步骤 4 重登）

6升级 / 卸载

检查新版（仅检查不自动升级）
npx -y tapd-server-cli update

预期 ✓ Up to date (0.3.1) 或 ↑ Update available: 0.3.1 → 0.3.x，再加两条升级建议命令。网络失败仍 exit 0、不阻断。

登出（删 cookie）
npx -y tapd-server-cli logout

预期 ✓ Logged out. Cookie cleared 或 = No cookie file found, nothing to clear（文件不存在不算错）。

完全卸载
# 仅去 MCP 配置 + commands 目录
npx -y tapd-server-cli uninstall claude-code

# 同时清理 cookie + token 文件
npx -y tapd-server-cli uninstall claude-code --purge

验证点 PASS 标准

  • ~/.claude/commands/tapd-server-cli/ 整个目录被删除
  • ~/.claude.json 顶层 mcpServers.tapd 节被移除（其它 server 保留）
  • 原文件备份到 ~/.claude.json.bak.<timestamp>
  • 加 --purge 时 ~/.config/tapd-mcp/{cookie,token} 也被删
  • 不加 --purge 时上述两文件保留（汇总末尾会提示）

回滚预案

v0.3.x 系列是 v0.2.x 的破坏性后继
npm 不允许删除已发布版本。如果 v0.3.x 出现 critical bug，应发新 patch 修，不要试图 unpublish。Plugin 路径已彻底撤回，不存在回滚到 v0.2.x 的可能——0.2.x 用户需手动执行迁移命令（见下）。

用户从 v0.2.x 迁移到 v0.3.x

# 1. 卸载 0.2.x 时代的 plugin（如有）
> /plugin uninstall tapd-server-cli
> /plugin marketplace remove tapd-server-cli

# 2. 装最新 v0.3.x
npx -y tapd-server-cli@latest install claude-code

# 3. 重启 Claude Code，跑步骤 2-3 验证

maintainer 紧急 patch 流程（hotfix 模板，以 v0.3.<next> 为例）

  1. 从 main 切 release/v0.3.<next> 分支（或直接在 main 攒 commit，本仓 v0.3.1 即直接走 main 路径）
  2. 修 bug + 加测试 + 必要时写 OpenSpec change（fix-<name>）
  3. CHANGELOG 必须加 [0.3.<next>] - YYYY-MM-DD 段含 Fixed 节——release CI 的 Extract release notes 步骤会硬校验，缺失直接 fail
  4. PR + CI 绿 + merge → main（小改动可跳 PR 直接 push）
  5. npm version patch → git push origin main v0.3.<next>
  6. 等 release CI 自动 publish；用 § npm publish 验证 复核
  7. 有 OpenSpec change 时 openspec archive fix-<name> --yes → push
v0.3.1 的踩坑教训（写给未来的你）
  1. 提升 engines.node 是横切改动：4 处需要同步——package.json / 运行时自检 / ci.yml 矩阵 / release.yml 自身的 setup-node。最容易漏的是第 4 处——release.yml 的 npm test 步骤跑在它声明的 Node 版本上，而非 ci.yml 矩阵。
  2. CHANGELOG 顶部硬门禁：tag 推送后 release CI 第一步 extract-changelog.mjs 找不到 [<version>] 段直接 fail。npm version patch 不会自动给你写 CHANGELOG 段——必须先手动改 [Unreleased] 为正式版本号 + 重建空 [Unreleased]。
  3. tag 推错怎么改：git tag -d <tag> + git push origin :refs/tags/<tag> 删本地 + 远端 → fix → git tag <tag> 重打 → git push origin main <tag> 重推。release CI 会基于新 tag commit 重跑。
